xarray-ts opens a **single group** at a path and returns a flat `Dataset`.
Recursive, nested-group / `DataTree` traversal is intentionally **out of scope**
here — it belongs to a separate library, which plugs into this one through a
small, documented seam so the metadata-interpretation logic lives in exactly one
place.

## The seam

- **`datasetFromGroup(group, arrayNames)`** — the reusable core that turns one
  already-resolved zarrita `Group` (plus the names of its child arrays) into a
  `Dataset`. A hierarchy walker calls this **per node**.
- **`childArrayNames(contents, groupPath)`** — given a consolidated-metadata
  listing, the direct-child array names of a group.
- **`GroupNode`** — the tree-node contract (`{ path, dataset, children }`) an
  external walker produces and consumes.

```ts
import { datasetFromGroup, childArrayNames, type GroupNode } from "xarray-ts";
```

A tree walker resolves each zarr group, asks `childArrayNames` which arrays hang
directly off it, hands both to `datasetFromGroup`, and assembles the resulting
`Dataset`s into a tree of `GroupNode`s.

## openDatatree is a stub

Calling `openDatatree()` throws a `NotImplementedError` that points you here —
it exists so the intent is discoverable from the API surface.
